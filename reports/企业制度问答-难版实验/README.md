# 企业制度问答意图识别：准确率优势与置信度复核机制

> **一句话结论**：在「问句不含主题词、测试情境全新」的难版数据上，微调模型准确率 **58.63%**，
> 关键词基线（TF-IDF）**39.27%**，**高 19.4 个百分点**；
> 更关键的是，模型能输出**可用的置信度**——置信度 ≥ 0.5 的请求只占 49.2%，却只承担 16.4% 的错误，
> 让「自动执行 + 低置信转人工/模型」这条流水线第一次变得可算账。

---

## 1. 为什么需要一个「难」数据集

项目最初的意图数据集是关键词可解的：问「年假有几天」，标签就是「年休假」。
在这种数据上，TF-IDF 能拿 98.9%，微调 99.4%——**差 0.5 个点，说明这份数据测不出模型价值**。

真正的员工提问不长这样。他们说的是：

```
「我在这行干了 12 年，一年能歇多少天」     -> 年休假（句子里没有"年假"）
「我爷爷过世了，能给几天」                 -> 丧假
「去上海住一晚要四百多，怎么算钱」          -> 住宿
「我电脑开不了机，要怎么办」               -> 设备
```

所以本项目自建了一份**难版**数据：**问句里不出现主题词**，只能靠情境推断制度主题。

| 项 | 值 |
|---|---|
| 规模 | **40,000 条**（其中测试集 5,905 条） |
| 标签 | **25 个制度主题** + out_of_scope + chitchat = 27 类 |
| 知识来源 | 真实制度文档 58 条条款 |
| 情境库 | **194 个手写情境**（每个主题 3–10 个） |
| 平均长度 | 15.6 字（P90 = 20 字） |
| 噪声 | 8% 带错别字、随机语气词/开场白 |
| 切分 | **按情境分组**：测试集的情境训练时完全没见过 |

**切分方式是关键**：按情境分组，保证测试集是「新说法」而不是「同一句话的不同标点」。

---

## 2. 方法

| 项 | 设置 |
|---|---|
| 底座 | `hfl/chinese-macbert-base`（12 层 / 1.02 亿参数） |
| 训练方式 | 全参微调 + 线性分类头 |
| 损失 | 加权交叉熵（`w_c = N/(K·n_c)`，处理类别不平衡） |
| 优化 | AdamW，lr 2e-5，batch 64，3 轮，线性 warmup 10%，梯度裁剪 1.0 |
| 置信度 | softmax 最大概率，**经温度缩放校准**（T=2.05，在 dev 上拟合） |
| 硬件 | RTX 5060（8GB），约 76 秒/轮 |

**模型选择方式**（这条很重要）：dev 从训练分布中随机抽 8%，测试集才是「全新情境」。
早期版本把 dev 也做成「全新情境」，导致 dev 分数剧烈波动、选轮次变成掷骰子（best epoch 落到第 1 轮，等于拿欠拟合模型去测）。

## 3. 结果一：准确率优势

| 方法 | 准确率 | macro-F1 |
|---|---|---|
| 多数类 | 12.19% | 1.09% |
| **TF-IDF + 逻辑回归（关键词）** | **39.27%** | **28.80%** |
| **微调 MacBERT** | **58.63%** | **49.27%** |
| **提升** | **+19.36 点** | **+20.47 点** |

**为什么这次微调赢了 19 个点，而易版只赢 0.5 个点？**

| 数据集 | 问句里含主题词 | TF-IDF | MacBERT | 差距 |
|---|---|---|---|---|
| 易版（4 类动作） | 是 | 98.87% | 99.44% | +0.6 |
| 易版（22 类主题） | 是 | 98.09% | 95.26%（F1 +0.8） | 微调反而低 |
| **难版（27 类）** | **否** | **39.27%** | **58.63%** | **+19.4** |

**规律很清楚**：任务越依赖「情境 → 制度」的语义推断，微调的优势越大；一旦词面就等于标签，模型容量没有用武之地。

---

## 4. 结果二：置信度复核（本文重点）

### 4.1 先校准，置信度才可信

模型原始输出严重过度自信（同一句话给 0.998）。用温度缩放在 dev 上拟合一个标量：

| | 校准前 | 校准后 |
|---|---|---|
| 温度 T | 1.00 | **2.05** |
| ECE（期望校准误差） | 0.3748 | **0.1430** |
| 「我爷爷过世了」的置信度 | 0.998 | **0.794** |

**温度缩放不改变预测，只改变置信度的含义**——所以准确率不变，但 0.8 从此可以当阈值用了。

### 4.2 置信度把错误高度集中

测试集 5,905 条，总错误 2,443 条（准确率 58.63%），按置信度分档：

| 置信区间 | 条数 | 占比 | 该档准确率 | 承担的错误占比 |
|---|---|---|---|---|
| 0.0–0.3 | 1,350 | 22.9% | 23.7% | **42.2%** |
| 0.3–0.5 | 1,650 | 27.9% | 38.4% | **41.6%** |
| 0.5–0.7 | 1,179 | 20.0% | 72.4% | 13.3% |
| 0.7–0.9 | 1,726 | 29.2% | **95.8%** | **2.9%** |

- **置信度 < 0.5 的区域装下了 83.7% 的错误**
- **置信度 ≥ 0.7 的区域只占 2.9% 的错误**，且该档准确率 95.8%

### 4.3 与关键词基线的置信度对比

TF-IDF 也能输出概率（`predict_proba`），但它的概率分布是「要么很确定、要么瞎猜」：

| | MacBERT（校准后） | TF-IDF |
|---|---|---|
| 整体准确率 | 58.63% | 39.27% |
| 平均置信度 | — | 0.316 |
| ECE | 0.143 | 0.093 |
| **≥0.7 的覆盖** | **29.2%** | 13.2% |
| **≥0.7 的准确率** | 95.8% | 100% |
| **≥0.5 的覆盖** | **49.2%** | 17.3% |
| ≥0.5 的准确率 | 86.2% | 100% |

**关键差异不在「谁的高置信更准」，而在「高置信能覆盖多少流量」**：

- 模型敢自动处理 **49.2%** 的请求，准确率 86.2%
- 关键词模型只敢处理 **17.3%**，其余 82.7% 全部落入「不确定」区间
- 换句话说：**TF-IDF 的置信度只能筛出一小撮，模型的置信度能筛出一半**

### 4.4 流水线收益（三档策略）

| 置信度 | 流量占比 | 该档错误率 | 动作 | token |
|---|---|---|---|---|
| ≥ 0.7 | 29.2% | 4.2% | 直接执行（查制度条款） | 0 |
| 0.5–0.7 | 20.0% | 27.6% | 执行但标记 `needs_review`，事后抽检 | 0 |
| < 0.5 | 50.8% | 68.2% | 用 `top_k` 反问澄清，或交大模型 | 0 或 1 次 |

**闸门效果**：

| 策略 | 自动执行比例 | 自动执行部分的错误率 | **被拦下的错误** |
|---|---|---|---|
| 不设闸门（全自动） | 100% | 41.4% | 0% |
| 阈值 0.5 | 49.2% | 13.7% | **83.7%** |
| 阈值 0.7 | 29.2% | 4.2% | **97.1%** |

**这就是「依靠置信度的 review 优势」**：不设闸门时，41% 的回答是错的；设 0.7 阈值后，自动发出的回答错误率降到 4.2%，代价是 71% 的流量进入复核/追问——而**追问本身是 0 token 的**。

---

## 5. 结果三：高置信错误是什么

72 条高置信错误（≥0.7）里，典型长这样：

```
0.72  真实=离职   预测=年休假   「我还有年假没休，有没有上限啊？」
```

**按语义判成「年休假」完全合理**——它问的就是年假。标成「离职」，是因为它出自「离职」情境（离职时年假怎么处理）。

**结论：高置信错误主要是「一句话同时属于两个主题」的标签歧义，不是模型能力问题。**
这也解释了为什么继续堆数据收益递减——数据再多，也解决不了「一句话两个答案」。

---

## 6. 限制（必须写）

1. **绝对准确率只有 58.6%**：因为测试情境是严格留出的（冷启动场景），不代表日常使用精度。
2. **数据是模板生成的**：情境由人工撰写（194 个），问法由模板组合。虽然做了同义替换、错别字、复合句，仍与真实用户分布有差距。
3. **复合问句已从训练集中移除**：早期版本含 15% 复合问句（一句话两个主题却只标一个），实测使准确率虚降 3 个点；这是标签歧义，不属于单标签任务。
4. **校准在 dev 上拟合**，dev 与测试分布不同，所以 ECE 0.143 仍偏高（理想 <0.05）。
5. **未与 2024 年工业做法对比**（如 EMNLP 2024 的 LLM + 不确定性路由），这是后续工作。

## 7. 复现

```powershell
$env:INTENT_DATASET = "enterprise_hard"

# 1. 生成 4 万条难版数据（194 个情境）
.venv\Scripts\python.exe data\gen_hard_faq.py --n 40000

# 2. 切分（test = 全新情境；dev = 训练分布抽 8%）
.venv\Scripts\python.exe train\prepare_enterprise.py --src data/raw/enterprise_hard/questions.jsonl

# 3. 基线 + 微调 + 评测
.venv\Scripts\python.exe train\baseline.py
.venv\Scripts\python.exe train\finetune.py --epochs 3 --batch-size 64 --lr 2e-5 --save-last
.venv\Scripts\python.exe train\evaluate.py

# 4. 温度校准（置信度变得可用）
.venv\Scripts\python.exe train\calibrate.py --split dev
```

产物：

| 文件 | 内容 |
|---|---|
| `data/enterprise_hard/{train,dev,test}.jsonl` | 40K / 2.7K / 5.9K |
| `models/enterprise_hard/intent-bert/` | 微调权重 |
| `models/enterprise_hard/calibration.json` | T=2.05、ECE 前后、可靠性表 |
| `eval/enterprise_hard/report_offline.json` | 全套指标 + 混淆矩阵 |

## 8. 结论

1. **准确率**：难版数据上微调 **58.63%** vs 关键词 **39.27%**，**+19.4 点**；而在关键词可解的易版数据上只差 0.5 点——**模型的优势来自语义推断，不是记忆**。
2. **置信度复核**：校准后（ECE 0.375→0.143），**阈值 0.7 能拦下 97.1% 的错误**，只放行 29.2% 的流量；阈值 0.5 放行 49.2%、拦下 83.6%。
3. **相对关键词模型的优势不只在准确率**：它的高置信区间能覆盖 **49.2%** 的流量（关键词模型只有 17.3%），这才是「可自动化比例」的真实差距。
4. **剩余错误的天花板是标签定义**，不是模型容量：一句话两个主题的高置信错误，需要多标签任务或追问机制来解决。
